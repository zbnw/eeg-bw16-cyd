# 安装与使用（0.2.0）

## 环境

- 硬件和接线按 [接线与上电](01_接线与上电.md)，板型仍为 BW16 与 ESP32-CYD。
- 编译环境：Arduino CLI、ESP32 core、AmebaD core；当前源码在 ESP32 core 3.1.1 / AmebaD 3.1.7 下验证。首次编译前需按各平台说明安装 cores。
- Python 3.11+；网页网关依赖见 `tools/requirements.txt`。
- 串口号每次连接后重新确认，不能把固定端口号当成某一块板的标识。

## 编译与烧录

推荐运行 `python tools/build_firmware.py --target all`，生成新的构建目录与校验清单。脚本使用项目内 CLI 副本（如果存在），否则查找 PATH；也可用 `--cli` 指定。
手工编译必须加入 `--libraries libraries`；完整命令见根目录 README。
先更新 CYD，再更新 BW16，可让新 CYD 先兼容旧 BW16 的三种数据通知。
具体 CYD 上传命令、BW16 厂商上传工具和镜像校验步骤见 [升级说明](09_v0.2升级与验收.md)。

烧录前关闭网关、串口监视器、SSCOM、MindViewer 和采集脚本。BW16 的 Burn/RST 是下载控制，
烧录后仅按 RST 启动；不要通过 Burn 灯推断数据是否正常。

## LCD 信息

| 显示 | 含义 |
| --- | --- |
| BLE SEARCH | 当前未连接，进行间隔扫描 |
| BLE LIVE / xxx/S | 最近 2 秒内收到 raw；显示的是 CYD 接收速率 |
| BLE NO DATA | BLE 已连接，但最近没有 raw；健康通知不能代替 raw |
| UART LIVE / NO DATA 状态 | 备用串口模式，按 raw 新鲜度显示 LIVE / NO DATA |
| V0.2.0 | 当前运行的应用版本 |
| SIGNAL -- | 指标缺失或超过 3 秒未更新 |
| SIGNAL 0 GOOD | 模块报告 signal=0 |
| SIGNAL 200 NO CONTACT | 模块报告 signal=200 |
| SIGNAL 1..199 NOISY | 模块报告非零干扰值 |
| A / M | 模块 attention / meditation；缺失字段显示 -1 |
| G / Q / E / R | BLE 序号间断事件 / 接收队列丢弃 / 本地错误合计 / 观察到的断连事件 |
| BIN / JSON | 当前 USB 输出模式 |

波形仍为线性自适应，最近 1024 点决定范围，每 3 点绘制一列的极值，范围每约 125 ms 更新。
历史列不会随新范围重新绘制；整屏不是同一固定纵轴，不能据屏幕像素作定量幅值比较。
缩放变化时不连接采用不同比例的相邻点，已知间断后重建历史窗口。
没有对输出 raw 做平滑、压缩或滤波。

## USB 两种模式

上电默认 `BIN`，115200 8N1，应用只输出有效 EEG 二进制包，HEX 终端可看到 `AA AA`。
启动 ROM / 底层库的异常信息仍可能出现，电脑解析器需要能重新同步。

ASCII 命令以换行结束：

- `json\n`：切到 JSON Lines，并输出含版本、设备 ID、会话 ID 的 hello。
- `status\n`：仅 JSON 模式立即输出健康统计。
- `binary\n`：切回二进制，不添加文本确认。
- 未知或过长命令忽略；这些命令不修改 EEG 模块设置。

切换时旧格式数据可能仍在串口缓冲区。项目采集脚本和网关负责等待、丢弃边界残留并重新同步。
JSON 模式是本次新增应用模式，旧版 CYD 不支持；旧固件接网关请使用 `--format binary`。

## 网页与记录

```powershell
./.venv/Scripts/python.exe tools/eeg_gateway.py --port COMx --record recordings/session-001.jsonl
```

打开网关打印的地址。Ctrl+C 退出时网关尝试恢复 BIN；异常退出或端口已拔除不能保证恢复，
必要时发送 `binary\n` 或复位 CYD。网页导出最多保留最近 100000 点，长时间记录使用 `--record`。
使用原始 BIN 采集时先退出网关，见 [采集说明](04_采集与数据处理.md)。
