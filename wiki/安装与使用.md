# 安装与使用：从零开始运行 0.2.0

本页按“准备 → 构建 → 烧录 → 上电 → 电脑采集 → 排障”的顺序说明。项目由 EEG V6.1、BW16、ESP32-CYD 和可选的电脑网页组成。首次操作请在**无人佩戴电极**的台架状态进行，并先阅读[安全边界](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E5%8E%9F%E5%9E%8B%E5%AE%89%E5%85%A8%E8%BE%B9%E7%95%8C)。

## 1. 确认硬件与连接方式

需要一块 ESP32-CYD（ESP32-2432S028R 类）、一块与目标板型匹配的 BW16、一块 Sichiray EEG V6.1、合适的稳压电源、数据 USB 线和两端 UART 导线。确认模块实物版本与焊盘方向后，按[接线与上电](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E6%8E%A5%E7%BA%BF%E4%B8%8E%E4%B8%8A%E7%94%B5)连接 EEG `TX` → BW16 `PB2/D5`、EEG 数字 `GND` → BW16 `GND`。EEG `RX` 不连接；两端供电正极分开。CYD 与 BW16 只用 BLE 通信，不接串口线或地线。

首次上电前先用万用表检查极性、两路稳压电压、意外短路和 EEG `TX` 电平。不要仅凭“板子亮灯”推断电气连接正确。电极参考地与数字 `GND` 不同，不能随意短接。具体焊盘、供电和电极网络见[详细接线](https://github.com/zbnw/eeg-bw16-cyd/wiki/EEG%E6%8E%A5%E7%BA%BF%E8%AF%A6%E8%A7%A3)。

## 2. 准备电脑环境

项目验证时的编译环境为 Arduino CLI、ESP32 core 3.1.1、AmebaD core 3.1.7；Python 工具要求 Python 3.11+。在新电脑上，应先按各开发板平台说明安装 Arduino CLI 与对应板型。仓库不打包厂商工具链。运行以下命令检查可执行程序是否可用：

```powershell
arduino-cli version
arduino-cli board list
python --version
```

`arduino-cli board list` 显示的 COM 端口会随插拔变化。先单独插 CYD 记录其端口，再单独插 BW16 记录其端口；不要假定历史上的 `COM3` 或 `COM4` 仍对应相同设备。烧录和监视串口之前，关闭网关、SSCOM、Arduino 串口监视器、MindViewer 等会占用端口的程序。

若只运行网页演示模式，不需要硬件或 Python；直接打开 [web/index.html](https://github.com/zbnw/eeg-bw16-cyd/blob/main/web/index.html)，确认页面标记为 `DEMO`。演示曲线是合成数据。

## 3. 构建固件

在仓库根目录运行：

```powershell
python tools/build_firmware.py --target all
```

脚本会优先使用项目本地 Arduino CLI 副本（若存在），否则从 `PATH` 查找；也可用 `--cli` 指定路径。它将输出放进一个新的 `.build/release-日期时间/` 文件夹，并写入构建日志和 `manifest.json`。这一步**只编译，不烧录**。

若手工编译，必须加 `--libraries libraries` 才能找到共用 `EegCore`：

```powershell
arduino-cli compile --fqbn esp32:esp32:jczn_2432s028r --libraries libraries --build-path .build/local-cyd sketches/esp32_cyd_starter
arduino-cli compile --fqbn realtek:AmebaD:Ai-Thinker_BW16 --libraries libraries --build-path .build/local-bw16 sketches/bw16_ble_eeg
```

BW16 工具链可能向安装目录写中间文件。若日志出现 `Access denied`，即使命令退出码是 0，也不要把该次构建当成成功；排除权限问题后重新生成镜像并核对清单。

## 4. 依次烧录 CYD 与 BW16

**先烧录 CYD，后烧录 BW16。** 新 CYD 能兼容旧 BW16 的数据通知；新 BW16 多出的健康通知可能被旧 CYD 记为格式错误。以下仅给出流程，具体命令、镜像路径选择、哈希校验和回退见[0.2.0 升级与验收](https://github.com/zbnw/eeg-bw16-cyd/wiki/0.2%E5%8D%87%E7%BA%A7%E4%B8%8E%E9%AA%8C%E6%94%B6)。

1. 在无人佩戴状态下，断开占用 CYD 串口的程序；从 `arduino-cli board list` 确认当前 CYD 端口。
2. 使用本次构建的 CYD 镜像和 `esp32:esp32:jczn_2432s028r` 板型上传。重启后检查 LCD 出现 `V0.2.0`，且没有反复复位。
3. 确认本次 BW16 BLE 构建的 `km0_km4_image2.bin`，复制到厂商上传工具要求的目录，并比较两边 SHA-256。**不要使用工具目录里来源不明的残留镜像，也不要误刷原始字节转发诊断程序。**
4. 确认 BW16 当前 COM 端口，运行厂商上传工具。必须看到 `All images are sent successfully!`，随后仅按 `RST` 启动。
5. 保存构建清单、烧录日志和设备显示版本。上传工具报告成功后仍要进行下述运行验收。

BW16 的 `Burn`/`RST` 用于下载控制，不要只凭某个 LED 判断程序是否运行。先处理设备启动问题，再检查 EEG 数据和 BLE。

## 5. 查看 CYD LCD

无人佩戴台架上电后，先让 EEG 与 BW16 运行，再启动 CYD。

| LCD 显示 | 如何理解 |
| --- | --- |
| `BLE SEARCH` | 尚未建立 BLE 连接，正在按间隔扫描 |
| `BLE LIVE`、`xxx/S` | 最近约 2 秒收到原始样本；速率是 CYD 接收速率 |
| `BLE NO DATA` | BLE 已连接，但最近没有原始样本；健康通知不能代替样本 |
| `V0.2.0` | 当前运行的 CYD 应用版本 |
| `SIGNAL --` | 指标尚未收到或超过约 3 秒未更新 |
| `SIGNAL 0 GOOD` | 模块报告信号值为 0 |
| `SIGNAL 200 NO CONTACT` | 模块报告信号值为 200 |
| `SIGNAL 1..199 NOISY` | 模块报告非零干扰值 |
| `A / M` | 模块的注意力/放松度字段；缺失时显示 `-1` |
| `G / Q / E / R` | BLE 序号间断事件、接收队列丢弃、本地错误合计、观察到的断连事件 |
| `BIN / JSON` | 当前 USB 输出格式 |

波形以最近样本的最小/最大值自适应显示。不同历史列可能采用不同缩放，屏幕像素不能用于定量幅值比较。USB 输出的原始数值不经过 LCD 的缩放、平滑或滤波。

## 6. 选择 USB 输出与电脑采集

CYD 上电默认 `BIN`，USB 串口参数为 `115200 8N1`，输出有效 EEG 二进制包。十六进制终端可以看到 `AA AA 04 ...` 原始包和 `AA AA 20 ...` 指标包。启动 ROM 可能输出额外信息，电脑解析器会重新同步。

向串口发送带换行的 ASCII 命令可切换应用输出：

| 命令 | 效果 |
| --- | --- |
| `json\n` | 切到 JSON Lines，并发送包含版本、设备 ID、会话 ID 的 `hello` |
| `status\n` | JSON 模式立即发送一次健康状态 |
| `binary\n` | 恢复二进制模式，无额外文字确认 |

命令不会修改 EEG 模块设置。格式切换边界可能残留上一个格式的串口字节，网关会等待并重新同步。旧版 CYD 不支持 JSON 命令，连接旧固件时要为网关指定 `--format binary`。

## 7. 启动实时网页与记录

在项目根目录创建 Python 虚拟环境并安装依赖：

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r tools/requirements.txt
./.venv/Scripts/python.exe tools/eeg_gateway.py --port COMx --record recordings/session-001.jsonl
```

将 `COMx` 换成 **CYD** 当前端口。`--record` 会新建 JSONL 文件并拒绝覆盖同名文件；改用新的会话文件名即可继续记录。打开终端打印的完整网页地址，默认使用本机 HTTP 端口 8080 和 WebSocket 端口 8765。网关只监听 `127.0.0.1`，不需要 CYD Wi-Fi。`LIVE` 要求有新样本，`STALE` 表示样本暂停；若页面为 `DEMO`，通常是打开了不含 `ws` 参数的普通页面。

网页 CSV 导出只保留最近最多 100000 点，长时间记录应使用 `--record` 或原始 BIN 采集工具。浏览器时间轴和导出时间是根据接收时刻与近似采样率推算的，不是模块提供的硬件时间戳。指标、频段、丢包计数的解释见[网页与网关说明](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E7%BD%91%E9%A1%B5%E4%B8%8E%E7%BD%91%E5%85%B3%E4%BD%BF%E7%94%A8)和[协议字段](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E7%BD%91%E9%A1%B5%E4%B8%8E%E7%BD%91%E5%85%B3%E5%8D%8F%E8%AE%AE)。

结束时按 `Ctrl+C`，网关会尝试让 CYD 恢复 BIN。若异常退出或 USB 已断开，可在串口空闲后发送 `binary\n` 或复位 CYD。网关和其它串口程序不能同时打开同一端口。

## 8. 回放、诊断和下一步

拥有本机 BIN 采集文件时，可用 `--replay 文件路径 --sample-rate 近似采样率` 回放；网页会显示 `REPLAY`，不会将其标成实时设备。仓库不包含个人 EEG 采样文件。

第一次实机验收建议按[升级验收表](https://github.com/zbnw/eeg-bw16-cyd/wiki/0.2%E5%8D%87%E7%BA%A7%E4%B8%8E%E9%AA%8C%E6%94%B6)依次检查：CYD 单独启动、BW16 连接、EEG 断电与恢复、BW16 重启重连、网关会话、30 分钟无人佩戴运行。若出现 `BLE SEARCH`、`NO DATA`、串口乱码或网页停在 `DEMO`，按[故障排查](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E6%95%85%E9%9A%9C%E6%8E%92%E6%9F%A5)逐段定位，而不是同时改动接线、固件和软件。
