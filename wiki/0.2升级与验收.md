# 0.2.0 升级、回退与验收

迭代日期：2026-09-25 至 2026-09-26。项目设备曾上传 CYD 与 BW16 的 0.2.0；其它设备应独立构建、烧录和验收。软件构建与回归结果见[测试记录](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E6%B5%8B%E8%AF%95%E8%AE%B0%E5%BD%95)。
每台电脑本地的 `.build/` 保存其镜像和构建日志；该目录不包含在公开源码发布中。克隆仓库后必须先构建，不能照抄历史构建目录或直接使用别人的固件文件。

## 这次改变了什么

| 范围 | 改变 | 对实际使用的影响 |
| --- | --- | --- |
| 共用协议核心 | 包边界恢复、残包超时、按字段解码、完整校验后提交 | 两端行为一致，异常包不会局部污染指标 |
| BW16 | 32 条发送队列、3 ms 最小提交间隔、两半指标成对入队、每秒健康报告 | 处理突发输入和积压时有界，能够观察本地丢弃 |
| CYD | 96 条接收队列、重复/缺帧处理、会话清理、1 秒扫描与退避 | 减少旧会话残留，区分 BLE 断流和 EEG 无数据 |
| LCD | 保留底层驱动，恢复网格，状态按需刷新，显示版本与计数 | 减少重复绘制，可现场查看链路状态 |
| USB | 默认 BIN，新增显式切换的 JSONL | 旧采集仍可用，新工具能保存版本和错误统计 |
| 网关 | 真实串口与历史回放、自动重连、JSONL 记录 | 无需 CYD Wi-Fi 即可接通现有网页 |
| 网页 | 样本超时、指标过期、回放标记、极值绘制、动态坐标 | 停流不会被心跳掩盖，导出保留原会话信息 |
| 工具 | 防覆盖采集、断开后保留残档、SHA-256、可复核构建 | 保护已有记录，明确知道烧录的是哪一份镜像 |

LCD MOSI=13 / SCLK=14 / CS=15 / DC=2 / RST=4 / BL=21、57600 EEG UART 和默认 BLE 路径均未改变。
未重新引入 TFT_eSPI，未改变电极、电源或底板方案。BW16 直通诊断草图仍发送收到的全部字节，只改成小批量 USB 写入。

## 升级顺序和兼容性

1. 先烧录 CYD 0.2.0，旧 BW16 的 01/02/03 数据通知仍能接收；此时 BW16 健康字段未知。
2. 再烧录 BW16 0.2.0，新增 04 健康通知才会出现。
3. 如暂时保留旧 CYD，在 BW16 board_config.h 中将 kSendHealth=false 后编译，否则旧 CYD 会把新通知计为格式错误。
4. 新网页可用 --format binary 接旧 CYD；旧固件不会响应 json 命令。

### CYD

先在项目根目录运行 `python tools/build_firmware.py --target all`，从终端最后打印的 `Manifest` 路径取得**本次**构建目录，检查 `manifest.json` 中的 `verified_release` 为 `true`、`targets.cyd.verified_build` 为 `true`。然后确认 COM 号并关闭所有占用串口的程序。下例中的目录名须替换成实际输出：

```powershell
arduino-cli board list
$cydPort = 'COMx' # 替换为 CYD 当前串口
$releaseDir = '.build/release-YYYYMMDD-HHMMSS' # 改成本次 manifest.json 所在目录
arduino-cli upload --fqbn esp32:esp32:jczn_2432s028r --port $cydPort --build-path (Join-Path $releaseDir 'cyd') sketches/esp32_cyd_starter
```

上传工具成功后仍需观察 LCD 是否显示 `V0.2.0`，并确认启动日志、BLE 扫描与接收。项目设备的历史烧录记录不能代替读者设备上的验收。

### BW16

厂商上传工具从自己的安装目录读取 km0_km4_image2.bin。其它 BW16 草图的编译会覆盖该位置，
因此**上传前必须明确复制所选 BLE 镜像并核对哈希**。不要拿 reader 镜像或工具目录的残留文件直接上传。

以下命令展示一种 Windows 安装路径和镜像准备方式。使用同一个 `$releaseDir`，并确认 `manifest.json` 中 `targets.bw16.verified_build` 为 `true`。实际工具版本目录、BW16 串口号都要按本机环境调整。烧录后按 BW16 的 `RST` 键启动，再确认 CYD BLE 接收。

```powershell
$bwTools = Join-Path $env:LOCALAPPDATA 'Arduino15/packages/realtek/tools/ameba_d_tools/1.1.3'
$bwImage = Join-Path $releaseDir 'bw16/km0_km4_image2.bin'
Copy-Item -LiteralPath $bwImage -Destination (Join-Path $bwTools 'km0_km4_image2.bin') -Force
$sourceHash = (Get-FileHash -LiteralPath $bwImage -Algorithm SHA256).Hash
$stagedHash = (Get-FileHash -LiteralPath (Join-Path $bwTools 'km0_km4_image2.bin') -Algorithm SHA256).Hash
if ($sourceHash -ne $stagedHash) { throw 'BW16 image mismatch' }
$bwPort = 'COMx' # 替换为 BW16 当前串口
& (Join-Path $bwTools 'upload_image_tool_windows.exe') $bwTools $bwPort Ai-Thinker_BW16 Enable Disable 1500000
```

厂商工具路径需与本机安装一致。
要求上传日志含 All images are sent successfully!，之后仅按 RST 启动，保存日志与镜像哈希。
调试 USB 接在 BW16 时沿用项目原有的无人佩戴台架测试要求。

## 建议按顺序验收

| 场景 | 预期 | 保存证据 |
| --- | --- | --- |
| 仅 CYD 上电，BW16 关闭 | LCD 正常、显示版本和 SEARCH，不反复重启 | LCD 照片、启动日志 |
| BW16 上电，EEG 正常输出 | 转为 LIVE，显示接收速率，BIN 可解析 | 30 秒 BIN 及统计 |
| 新网关 JSON 连接 | hello 显示 CYD 0.2.0，status 显示 BW16 0.2.0 | JSONL |
| EEG 断电，BW16 保持上电 | raw 停止、LCD NO DATA、网页 STALE，健康信息仍可到达 | 时间标记、JSONL |
| 恢复 EEG 电源 | raw 和指标恢复，无需重新烧录 | JSONL |
| BW16 断电再上电，重复 5 次 | CYD 重新扫描并恢复，旧指标不继续显示 | 每次恢复时间与计数 |
| CYD 复位且网关仍开着 | 网关重新请求 JSON，新的 hello / 会话出现 | JSONL |
| 拔插 CYD USB | 网关提示重试，端口恢复后重新连接；端口变更需重启网关 | 终端日志 |
| 无人佩戴连续运行 30 分钟 | 不发生 watchdog/reset；G/Q/E、发送端错误没有持续无解释增长 | JSONL、LCD、堆变化 |
| 正常关闭网关后 BIN 采集 | 输出可解析，不夹入应用诊断文本 | BIN 与元数据 |

不要把所有计数都必须为零当作无条件保证；记录事件发生时的无线距离、重置、供电和主机状态再定位。
数秒扫描退避以及底层连接调用会使重连耗时变化。本版尚未承诺严格恢复时限或无损无线传输。

## 回退

如果手中有此前自行保存的固件源码或镜像与构建清单，可恢复对应旧草图和 `board_config.h`，重新编译、烧录；旧 CYD 配旧 BW16 是完整回退组合。公开仓库不提供任何人的本地备份快照。
仅回退 CYD 时关闭新 BW16 的健康通知，或同时恢复 BW16。
历史日志、采样记录和本机烧录结果不纳入公开源码；它们不能代替当前版本的实机验收。

更多软件验证记录见 [测试记录](https://github.com/zbnw/eeg-bw16-cyd/wiki/%E6%B5%8B%E8%AF%95%E8%AE%B0%E5%BD%95)。
